================================================================================
                    iOS WebRTC 推流端 - 防花屏修改方案
                              v10.1
================================================================================

【目标】
- 极端弱网（1格信号）不花屏
- 宁可冻结画面，也不显示马赛克
- 快速 I 帧恢复

================================================================================
                           核心修改（必须做）
================================================================================

【1】GOP 改为 0.5-1 秒（最关键！）
--------------------------------------------------------------------------------
原来：
    videoEncoder.setKeyFrameInterval(2.0)  // 2秒

改为：
    videoEncoder.setKeyFrameInterval(0.5)  // 极端弱网推荐 0.5 秒
    // 或者
    videoEncoder.setKeyFrameInterval(1.0)  // 正常弱网推荐 1 秒

说明：GOP 越短，花屏恢复越快。极端弱网必须 0.5 秒。


【2】收到 PLI 必须立即插 I 帧（不能延迟！）
--------------------------------------------------------------------------------
// RTCVideoEncoder 或 RTCPeerConnection 回调
func onPLIReceived() {
    // 🔥 立即强制插入关键帧
    videoEncoder.forceKeyFrame()
    print("🔑 收到PLI，立即插入I帧")
}

说明：PC 端检测到花屏/丢帧会发送 PLI，iOS 必须立即响应。


【3】弱网自动降帧 + 降码率
--------------------------------------------------------------------------------
收到 PC 端的 set_fps 指令时：

func handleSetFps(fps: Int, urgency: String, reason: String) {
    switch urgency {
    case "critical":
        // 🚨 紧急：50ms 内执行
        videoEncoder.setFrameRate(fps)
        videoEncoder.setBitrate(currentBitrate * 0.5)  // 码率降 50%
        videoEncoder.forceKeyFrame()  // 立即插 I 帧
        
    case "high":
        // ⚡ 高优先级：200ms 内执行
        videoEncoder.setFrameRate(fps)
        videoEncoder.setBitrate(currentBitrate * 0.7)  // 码率降 30%
        videoEncoder.forceKeyFrame()
        
    case "normal":
        // 正常：可短暂过渡
        videoEncoder.setFrameRate(fps)
        
    case "low":
        // 低优先级：平滑过渡（升帧）
        smoothTransitionToFps(fps)
    }
    
    print("📉 帧率调整: \(fps)fps, urgency=\(urgency), reason=\(reason)")
}


【4】PTS 透传（不要编码器重写）
--------------------------------------------------------------------------------
❌ 错误做法：
    encoder.outputTimestamp = CMTime(...)  // 编码器自己生成时间戳

✅ 正确做法：
    encoder.outputTimestamp = sampleBuffer.presentationTimeStamp  // 透传采集层 PTS

说明：PTS 重写会导致 PC 端时序校准失效。


【5】FEC 必须开启
--------------------------------------------------------------------------------
确保 SDP 中包含：
    a=rtpmap:xxx red/90000
    a=rtpmap:xxx ulpfec/90000

WebRTC 默认支持 FEC，确保没有被禁用。

说明：FEC 前向纠错在丢包 <10% 时能显著减少花屏。

================================================================================
                           FAQ
================================================================================

Q: 为什么 GOP 要改短？
A: GOP 是两个 I 帧之间的间隔。弱网丢帧后，必须等到下一个 I 帧才能恢复画面。
   GOP=2秒 意味着最长要等 2 秒才能恢复；GOP=0.5秒 最长等 0.5 秒。

Q: 为什么收到 PLI 要立即插 I 帧？
A: PLI (Picture Loss Indication) 是 PC 端检测到丢帧/花屏后发出的请求。
   立即响应可以最快恢复画面。

Q: 为什么弱网要降码率？
A: 弱网带宽有限，高码率会导致更多丢包，反而更卡。
   降码率后丢包减少，反而更流畅。

Q: FEC 是什么？
A: Forward Error Correction，前向纠错。发送冗余数据，接收端可以恢复丢失的包。
   丢包 <10% 时效果很好。
