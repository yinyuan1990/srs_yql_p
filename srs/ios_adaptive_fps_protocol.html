📱 iOS 自适应帧率对接文档

版本：v1.0    更新日期：2025-01-31

1. 概述

本文档定义 PC 端与 iOS 端之间的自适应帧率控制信令协议，用于在弱网环境下实现平滑降帧/升帧。

核心原则：
  • PC 端负责网络状态检测与决策
  • iOS 端负责执行帧率调整
  • 信令必须低延迟、高优先级传输

1.1 帧率四档定义

档位 帧率 (fps) 建议码率 适用场景
档位1（最高） 60 fps 8-12 Mbps 网络优秀，满帧体验
档位2 45 fps 6-8 Mbps 网络良好，轻微降级
档位3 30 fps 4-6 Mbps 网络一般，中等降级
档位4（最低） 15 fps 2-3 Mbps 极端弱网，保流优先
说明：分辨率保持不变，仅通过帧率四档平滑调节；码率随帧率同步微调。

2. 信令通道

2.1 推荐方式（优先级从高到低）

方式 延迟 可靠性 说明
WebRTC DataChannel（推荐） ~10-50ms 可配置 复用现有连接，延迟最低
WebSocket 信令 ~50-150ms 可靠 通用方案，兼容性好
自定义 UDP ~5-30ms 不可靠 超低延迟，需自行保障

2.2 DataChannel 配置建议

// PC 端创建 DataChannel（高优先级、不可靠模式）
const adaptiveChannel = peerConnection.createDataChannel("adaptive-fps", {
    ordered: false,           // 不需要有序
    maxRetransmits: 0,        // 不重传（追求低延迟）
    priority: "high"          // 高优先级
});

// 或者可靠模式（推荐用于帧率控制）
const adaptiveChannel = peerConnection.createDataChannel("adaptive-fps", {
    ordered: true,
    maxRetransmits: 3,        // 最多重传3次
    priority: "high"
});

3. 信令协议定义

3.1 PC → iOS：帧率控制指令

PC端发送 iOS端接收

{
    "type": "adaptive_fps_control",
    "version": "1.0",
    "timestamp": 1706745600000,
    "seq": 12345,
    "data": {
        "action": "adjust",
        "targetFps": 30,
        "targetBitrate": 5000000,
        "urgency": "normal",
        "reason": "jitter_high",
        "metrics": {
            "arrivalRate": 0.72,
            "jitterRatio": 0.45,
            "lossRate": 0.03,
            "rttMs": 180,
            "queueDepth": 2
        }
    }
}

字段说明

字段 类型 必填 说明
type string 必填 固定值 "adaptive_fps_control"
version string 必填 协议版本，当前 "1.0"
timestamp number 必填 Unix 毫秒时间戳
seq number 必填 序列号，用于去重和排序
data.action string 必填 "adjust" | "force" | "reset"
data.targetFps number 必填 目标帧率：15 / 30 / 45 / 60
data.targetBitrate number 可选 目标码率（bps）
data.urgency string 必填 "low" | "normal" | "high" | "critical"
data.reason string 可选 触发原因（用于日志/调试）
data.metrics object 可选 触发时的网络指标快照

action 枚举值

值 含义 iOS 响应
adjust 平滑调整 按四档就近切换，可平滑过渡
force 强制立即切换 立即切换到目标帧率，无过渡
reset 重置到初始帧率 恢复到用户配置的原始帧率

urgency 紧急度

值 含义 iOS 响应时限 触发场景
low 低优先级 ≤ 2000ms 升帧建议
normal 正常 ≤ 500ms 常规降帧
high 高优先级 ≤ 200ms 网络快速恶化
critical 紧急 ≤ 50ms 即将断流

reason 触发原因枚举

值 含义
arrival_low到达率不足（<85%）
jitter_high抖动过高（>30%）
loss_high丢包过高（>5%）
rtt_highRTT过高（>300ms）
queue_low队列不足（<3帧）
network_recover网络恢复，可升帧
user_request用户主动请求

3.2 iOS → PC：执行确认

iOS端发送 PC端接收

{
    "type": "adaptive_fps_ack",
    "version": "1.0",
    "timestamp": 1706745600050,
    "seq": 12345,
    "data": {
        "status": "applied",
        "appliedFps": 30,
        "appliedBitrate": 5000000,
        "execTimeMs": 35,
        "encoderState": "ok"
    }
}

字段说明

字段 类型 必填 说明
type string 必填 固定值 "adaptive_fps_ack"
seq number 必填 对应请求的序列号
data.status string 必填 "applied" | "rejected" | "pending"
data.appliedFps number 必填 实际应用的帧率
data.appliedBitrate number 可选 实际应用的码率
data.execTimeMs number 可选 执行耗时（毫秒）
data.encoderState string 可选 "ok" | "overload" | "error"

status 枚举值

值 含义 PC端处理
applied 已执行 确认生效，继续监控
rejected 拒绝执行 记录日志，可能需调整策略
pending 延迟执行中 等待后续 applied 确认

4. iOS 端快速响应机制

4.1 响应时序要求

1
PC 端检测到网络恶化，发送 adaptive_fps_control
↓
2
iOS 端收到信令（目标 ≤ 50ms 内收到）
↓
3
iOS 解析并调用编码器 API（目标 ≤ 30ms）
↓
4
编码器生效并输出新帧率码流
↓
5
iOS 发送 adaptive_fps_ack 确认
关键约束：从 PC 发送到 iOS 执行完成，总延迟应 ≤ 200ms（critical 级别应 ≤ 100ms）

4.2 iOS 端实现要点

4.2.1 信令监听（高优先级线程）

// Swift 伪代码 - DataChannel 监听
class AdaptiveFpsHandler {
    
    // 使用高优先级队列处理信令
    private let signalQueue = DispatchQueue(label: "adaptive.fps.signal", qos: .userInteractive)
    
    func onDataChannelMessage(_ message: Data) {
        signalQueue.async { [weak self] in
            guard let json = try? JSONDecoder().decode(AdaptiveFpsControl.self, from: message) else { return }
            
            if json.type == "adaptive_fps_control" {
                self?.handleFpsControl(json)
            }
        }
    }
    
    private func handleFpsControl(_ control: AdaptiveFpsControl) {
        let startTime = CFAbsoluteTimeGetCurrent()
        
        // 1. 根据 urgency 决定是否立即执行
        if control.data.urgency == "critical" || control.data.urgency == "high" {
            applyFpsImmediately(control.data.targetFps, bitrate: control.data.targetBitrate)
        } else {
            applyFpsSmoothly(control.data.targetFps, bitrate: control.data.targetBitrate)
        }
        
        // 2. 发送确认
        let execTime = (CFAbsoluteTimeGetCurrent() - startTime) * 1000
        sendAck(seq: control.seq, appliedFps: control.data.targetFps, execTimeMs: execTime)
    }
}

4.2.2 帧率切换逻辑（四档平滑）

// Swift 伪代码 - 四档帧率切换
class FpsController {
    
    static let fpsLevels: [Int] = [15, 30, 45, 60]
    
    private var currentFps: Int = 60
    private var targetFps: Int = 60
    private var isTransitioning: Bool = false
    
    // 立即切换（用于 high/critical 紧急度）
    func applyFpsImmediately(_ fps: Int, bitrate: Int?) {
        let normalizedFps = nearestFpsLevel(fps)
        currentFps = normalizedFps
        targetFps = normalizedFps
        
        // 直接调用编码器 API
        encoder.setFrameRate(normalizedFps)
        if let br = bitrate {
            encoder.setBitrate(br)
        }
    }
    
    // 平滑切换（用于 low/normal 紧急度）
    func applyFpsSmoothly(_ fps: Int, bitrate: Int?) {
        let normalizedFps = nearestFpsLevel(fps)
        targetFps = normalizedFps
        
        if !isTransitioning {
            startSmoothTransition()
        }
    }
    
    // 找到最近的档位
    private func nearestFpsLevel(_ fps: Int) -> Int {
        return FpsController.fpsLevels.min(by: { abs($0 - fps) < abs($1 - fps) }) ?? 30
    }
    
    // 平滑过渡（每档间隔 100-200ms）
    private func startSmoothTransition() {
        isTransitioning = true
        
        DispatchQueue.global(qos: .userInteractive).async { [weak self] in
            guard let self = self else { return }
            
            while self.currentFps != self.targetFps {
                let direction = self.targetFps > self.currentFps ? 1 : -1
                let currentIndex = FpsController.fpsLevels.firstIndex(of: self.currentFps) ?? 0
                let nextIndex = currentIndex + direction
                
                if nextIndex >= 0 && nextIndex < FpsController.fpsLevels.count {
                    self.currentFps = FpsController.fpsLevels[nextIndex]
                    
                    DispatchQueue.main.async {
                        self.encoder.setFrameRate(self.currentFps)
                    }
                    
                    // 降帧快（100ms），升帧慢（200ms）
                    let delay = direction < 0 ? 100 : 200
                    Thread.sleep(forTimeInterval: Double(delay) / 1000.0)
                } else {
                    break
                }
            }
            
            self.isTransitioning = false
        }
    }
}

4.2.3 编码器动态调参

// Swift 伪代码 - VideoToolbox 编码器动态调参
class H264Encoder {
    
    private var compressionSession: VTCompressionSession?
    
    // 动态设置帧率
    func setFrameRate(_ fps: Int) {
        guard let session = compressionSession else { return }
        
        let frameRate = CFNumberCreate(nil, .intType, [fps])
        VTSessionSetProperty(session, 
                            key: kVTCompressionPropertyKey_ExpectedFrameRate, 
                            value: frameRate)
    }
    
    // 动态设置码率
    func setBitrate(_ bitrate: Int) {
        guard let session = compressionSession else { return }
        
        let avgBitrate = CFNumberCreate(nil, .intType, [bitrate])
        VTSessionSetProperty(session, 
                            key: kVTCompressionPropertyKey_AverageBitRate, 
                            value: avgBitrate)
        
        // 同时设置数据速率限制（防止突发）
        let dataRateLimit = CFNumberCreate(nil, .intType, [Int(Double(bitrate) * 1.5)])
        VTSessionSetProperty(session, 
                            key: kVTCompressionPropertyKey_DataRateLimits, 
                            value: [dataRateLimit, 1.0] as CFArray)
    }
}

5. 完整闭环流程

5.1 降帧流程（弱网触发）

步骤 端 动作 时限
1 PC 检测到抖动 > 30% / 到达率 < 85% -
2 PC 计算目标帧率（如 60→30） ≤ 10ms
3 PC 发送 adaptive_fps_control，urgency=high -
4 iOS 收到信令，解析并验证 ≤ 50ms
5 iOS 调用编码器 setFrameRate(30) ≤ 30ms
6 iOS 发送 adaptive_fps_ack，status=applied -
7 PC 收到确认，更新状态机 -
总耗时目标：≤ 200ms（从检测到生效）

5.2 升帧流程（网络恢复）

步骤 端 动作 时限
1 PC 检测到抖动 < 20%、到达率 ≥ 90% 持续 ≥ 1s -
2 PC 计算目标帧率（如 30→45，每次升一档） ≤ 10ms
3 PC 发送 adaptive_fps_control，urgency=low -
4 iOS 收到信令，平滑切换 30→45 ≤ 500ms
5 iOS 发送 adaptive_fps_ack，status=applied -
6 PC 继续监控，若持续稳定可再升一档 -
升帧原则：慢升快降，每次只升一档，间隔 ≥ 1s

6. 异常处理

场景 检测方式 处理策略
信令超时 PC 端 500ms 未收到 ack 重发一次，仍无响应则记录日志
iOS 拒绝执行 ack.status = rejected PC 调整策略或降低期望
编码器过载 ack.encoderState = overload PC 暂停升帧请求，等待恢复
DataChannel 断开 连接状态监控 降级到 WebSocket 信令
连续降帧失败 连续 3 次 ack 失败 强制 reset 到最低档 15fps

7. 测试验证清单

测试项 验证点 通过标准
信令延迟 从 PC 发送到 iOS 收到 ≤ 100ms（P95）
执行延迟 从 iOS 收到到编码器生效 ≤ 50ms（P95）
四档切换 60→45→30→15 逐级切换 每档切换平滑，无卡顿
紧急降帧 critical 级别 60→15 总延迟 ≤ 150ms
升帧滞后 升帧需稳定 ≥ 1s 不会频繁升降抖动
弱网模拟 丢包 10%、RTT 500ms 能稳定在 15fps 档位
