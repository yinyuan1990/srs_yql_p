📱 iOS 自适应帧率对接文档 v2.0

版本：v2.0    更新日期：2025-01-31    信令通道：WebSocket（SRS）

1. 概述

核心策略：快降慢升
  • 降帧：大幅度、快速（四档跳：60→45→30→15）
  • 升帧：小幅度、缓慢（5-10fps 逐步升，每次间隔 ≥1秒）

1.1 职责划分

端 职责
PC端
  • 采集网络指标（到达率、抖动、队列）
  • 预测网络波动（趋势分析）
  • 计算目标帧率
  • 通过 WebSocket 发送 set_fps 指令
iOS端
  • 接收 set_fps 指令
  • 根据 urgency 决定执行方式
  • 调整编码器帧率/码率
  • 返回确认

1.2 帧率四档

档位 帧率 建议码率 场景
档位1 60 fps 8-12 Mbps 网络优秀
档位2 45 fps 6-8 Mbps 网络良好
档位3 30 fps 4-6 Mbps 网络一般
档位4 15 fps 2-3 Mbps 极端弱网

2. 信令协议（WebSocket）

在现有 set_fps 命令基础上扩展，新增 urgency 和 reason 字段。

2.1 PC → iOS：set_fps 指令

PC端发送 iOS端接收

{
    "cmd": "set_fps",
    "fps": 30,
    "urgency": "high",
    "reason": "jitter_high",
    "bitrate": 5000000,
    "timestamp": 1706745600000
}

字段说明

字段 类型 必填 说明
cmd string 必填 固定值 "set_fps"
fps number 必填 目标帧率（15/30/45/60 或任意值）
urgency string 新增 "critical" | "high" | "normal" | "low"
reason string 可选 触发原因（调试用）
bitrate number 可选 建议码率（bps）
timestamp number 可选 时间戳（毫秒）

⭐ urgency 紧急度（核心字段）

值 含义 iOS 执行方式 响应时限 使用场景
critical 紧急 立即执行，无过渡 ≤ 50ms 即将断流（队列≤1帧）
high 高优先级 立即执行，无过渡 ≤ 200ms 网络快速恶化
normal 正常 可短暂过渡（100-200ms） ≤ 500ms 常规降帧
low 低优先级 平滑过渡 ≤ 2000ms 升帧建议
iOS 端必须处理 urgency 字段：
  • critical / high：必须立即执行，不能有动画或过渡
  • normal：可以有短暂过渡
  • low：升帧时使用，可以平滑过渡
  • 如果字段缺失，默认按 normal 处理

reason 触发原因（调试用）

值 含义
predict_warning预测式预警（趋势分析触发）
predict_critical预测式紧急（趋势急剧恶化）
arrival_low到达率不足（<85%）
jitter_high抖动过高（>30%）
queue_low队列不足（<3帧）
rtt_highRTT过高（>300ms）
network_recover网络恢复，可升帧

2.2 iOS → PC：set_fps_ack 确认（可选）

iOS端发送 PC端接收

{
    "cmd": "set_fps_ack",
    "fps": 30,
    "status": "applied",
    "timestamp": 1706745600050
}
字段 类型 说明
cmd string 固定值 "set_fps_ack"
fps number 实际应用的帧率
status string "applied" | "rejected"
timestamp number 执行完成时间戳
确认消息为可选，PC 端不强制等待确认。但建议 iOS 端在执行完成后发送，方便 PC 端记录日志和调试。

3. iOS 端实现要点

3.1 指令处理逻辑

// Swift 伪代码

func onWebSocketMessage(_ message: String) {
    guard let data = message.data(using: .utf8),
          let json = try? JSONSerialization.jsonObject(with: data) as? [String: Any],
          let cmd = json["cmd"] as? String else { return }
    
    if cmd == "set_fps" {
        handleSetFps(json)
    }
}

func handleSetFps(_ json: [String: Any]) {
    guard let fps = json["fps"] as? Int else { return }
    
    let urgency = json["urgency"] as? String ?? "normal"
    let bitrate = json["bitrate"] as? Int
    let reason = json["reason"] as? String
    
    // 记录日志
    print("收到帧率指令: fps=\(fps), urgency=\(urgency), reason=\(reason ?? "")")
    
    // 根据 urgency 决定执行方式
    switch urgency {
    case "critical", "high":
        // ⭐ 立即执行，无过渡
        applyFpsImmediately(fps, bitrate: bitrate)
        
    case "normal":
        // 可短暂过渡
        applyFpsWithTransition(fps, bitrate: bitrate, duration: 0.15)
        
    case "low":
        // 平滑过渡（升帧）
        applyFpsWithTransition(fps, bitrate: bitrate, duration: 0.3)
        
    default:
        applyFpsWithTransition(fps, bitrate: bitrate, duration: 0.15)
    }
    
    // 发送确认（可选）
    sendAck(fps: fps)
}

3.2 编码器调参

// Swift 伪代码 - VideoToolbox

class VideoEncoder {
    private var session: VTCompressionSession?
    
    // 立即设置帧率（无过渡）
    func applyFpsImmediately(_ fps: Int, bitrate: Int?) {
        guard let session = session else { return }
        
        // 设置帧率
        var fpsValue = fps
        let fpsNumber = CFNumberCreate(nil, .intType, &fpsValue)
        VTSessionSetProperty(session, 
                            key: kVTCompressionPropertyKey_ExpectedFrameRate, 
                            value: fpsNumber)
        
        // 设置码率（如果提供）
        if let br = bitrate {
            var bitrateValue = br
            let bitrateNumber = CFNumberCreate(nil, .intType, &bitrateValue)
            VTSessionSetProperty(session,
                                key: kVTCompressionPropertyKey_AverageBitRate,
                                value: bitrateNumber)
        }
    }
    
    // 带过渡的帧率切换
    func applyFpsWithTransition(_ targetFps: Int, bitrate: Int?, duration: TimeInterval) {
        // 如果需要平滑过渡，可以在这里实现
        // 简单实现：直接调用 applyFpsImmediately
        applyFpsImmediately(targetFps, bitrate: bitrate)
    }
}

3.3 关键约束

iOS 端必须保证：
  • critical 紧急度：从收到指令到编码器生效 ≤ 50ms
  • high 紧急度：从收到指令到编码器生效 ≤ 200ms
  • 信令处理必须在高优先级线程（DispatchQueue.userInteractive）
  • 不能有阻塞操作

4. 降帧/升帧策略详解

4.1 降帧策略（PC 端控制）

策略：快降、大幅度
  • 四档跳：60 → 45 → 30 → 15
  • 紧急时可跳多档：60 → 30 或 60 → 15
触发条件 urgency 帧率调整 说明
队列 ≤ 1帧 critical 直接降到 15fps 即将断流，紧急保护
预测风险分 > 0.7 high 降两档（如 60→30） 趋势急剧恶化
预测风险分 > 0.5 high 降一档（如 60→45） 预测式预警
到达率 < 85% normal 降到到达帧率 网络能力不足
抖动 > 30% normal 降一档 网络不稳定
队列 < 3帧 normal 降一档 缓冲不足

4.2 升帧策略（PC 端控制）

策略：慢升、小幅度
  • 每次升 5-10fps
  • 升帧间隔 ≥ 1秒
  • 必须满足所有升帧条件才能升
升帧条件（全部满足） 阈值
抖动稳定 抖动比例 < 20%
抖动趋势稳定 抖动变化率 ≤ 0
到达率充足 到达率 ≥ 90%
队列充足 队列 ≥ 5帧
稳定持续时间 ≥ 1秒

升帧示例

    ↓ 稳定1秒后
升帧到: 30fps (urgency: low)
    ↓ ...
最终恢复到: 60fps

7. iOS 端改动总结

改动量：最小
  1. 在现有 set_fps 处理中，解析新增的 urgency 字段
  2. 根据 urgency 决定是立即执行还是平滑过渡
  3. 可选：发送 set_fps_ack 确认
// iOS 端核心改动（伪代码）

func handleSetFps(_ json: [String: Any]) {
    let fps = json["fps"] as! Int
    let urgency = json["urgency"] as? String ?? "normal"  // ⭐ 新增
    
    if urgency == "critical" || urgency == "high" {
        applyFpsImmediately(fps)  // ⭐ 立即执行
    } else {
        applyFpsWithTransition(fps)  // 平滑过渡
    }
}

8. FAQ

Q: 如果没有 urgency 字段怎么处理？

A: 默认按 normal 处理，保持向后兼容。

Q: fps 值必须是 15/30/45/60 吗？

A: 不是。PC 端升帧时会发送 20/25/35 等值，iOS 端应支持任意帧率。

Q: 需要返回确认吗？

A: 可选。建议返回，方便调试。但 PC 端不会阻塞等待确认。

Q: 码率怎么处理？

A: 如果指令中有 bitrate 字段，同步设置码率。如果没有，iOS 端可以根据帧率自行计算建议码率。
