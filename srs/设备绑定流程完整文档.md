## 概述

### 什么是设备绑定？

设备绑定是指将**控制端账号**与**设备端账号**建立关联关系的过程。绑定成功后，控制端可以远程控制设备端，实现远程查看、操作等功能。

### 绑定方式

- **二维码扫码绑定**：控制端生成二维码 → 设备端扫码 → 双方验证安全密码 → 绑定完成

### 核心特点

✅ **双向验证**：设备端和控制端都需要验证安全密码  
✅ **顺序要求**：设备端必须先验证，控制端后验证  
✅ **安全可靠**：使用JWT token认证 + 安全密码双重验证  
✅ **实时反馈**：无需轮询，双方验证成功后自动绑定  
✅ **绑定限制**：支持配置最大绑定数量（默认5个）

## 核心概念

### 用户类型

| 用户类型 | 说明 | 角色 |
|---------|------|------|
| `VIP_VIEW` | 设备端用户 | 被控制的设备，如iPad、手机 |
| `VIP_CONTROL` | 控制端用户 | 控制设备的终端，如PC、手机 |

### 绑定状态

| 状态 | 说明 |
|------|------|
| `PENDING` | 待完成：双方或一方尚未验证 |
| `ACTIVE` | 已激活：双方都已验证，绑定成功 |
| `INACTIVE` | 已解绑：绑定关系已终止 |

### 验证标志

| 字段 | 类型 | 说明 |
|------|------|------|
| `deviceVerified` | Boolean | 设备端是否已验证安全密码 |
| `controlVerified` | Boolean | 控制端是否已验证安全密码 |

### 步骤说明

#### 步骤1：控制端获取二维码数据

**操作端**：控制端（PC/手机APP）

1. 用户点击"绑定设备"按钮
2. 控制端调用API获取自己的用户名
3. 将用户名生成二维码并显示

**调用接口**：`GET /api/binding/qrcode`

**作用**：
- 验证控制端身份
- 获取控制端用户名用于生成二维码

---

#### 步骤2：设备端扫码创建绑定记录

**操作端**：设备端（iPad/手机APP）

1. 用户在设备端打开扫码功能
2. 扫描控制端显示的二维码，获取 `controlUsername`
3. APP自动获取当前登录的 `deviceUsername`
4. 立即调用创建绑定接口
5. 后端创建绑定记录，返回 `bindingId`

**调用接口**：`POST /api/binding/create`

**作用**：
- 创建一条状态为PENDING的绑定记录
- 建立设备端和控制端的关联
- 为后续验证步骤提供 `bindingId`

---

#### 步骤3：设备端验证安全密码

**操作端**：设备端（iPad/手机APP）

1. 创建绑定记录成功后，立即弹出输入框
2. 用户输入**设备端的安全密码**
3. 调用设备端验证接口
4. 后端验证密码，标记 `deviceVerified = true`
5. 此时绑定状态仍为PENDING，等待控制端验证

**调用接口**：`POST /api/binding/verify-device`

**作用**：
- 验证设备端用户身份
- 确保是设备端本人同意绑定
- 完成双向验证的第一步

⚠️ **重要**：设备端必须先验证，控制端才能验证！

---

#### 步骤4：控制端查询待验证绑定

**操作端**：控制端（PC/手机APP）

1. 在显示二维码后，定期调用查询接口（建议3-5秒一次）
2. 或者用户手动点击"刷新"按钮
3. 查询是否有设备端已扫码并验证的绑定
4. 获取 `bindingId` 和设备信息

**调用接口**：`GET /api/binding/pending`

**作用**：
- 发现有新的绑定请求
- 获取 `bindingId` 用于后续验证
- 显示设备信息供用户确认

---

#### 步骤5：控制端验证安全密码

**操作端**：控制端（PC/手机APP）

1. 从查询结果获取 `bindingId`
2. 显示设备信息，询问用户是否绑定
3. 弹出输入框，用户输入**设备端的安全密码**（注意：不是控制端的密码！）
4. 调用控制端验证接口
5. 后端先检查设备端是否已验证
6. 验证安全密码，标记 `controlVerified = true`
7. 双方都已验证，绑定状态变为ACTIVE
8. 控制端用户的 `deviceId` 被设置为设备端的 `deviceId`

**调用接口**：`POST /api/binding/verify-control`

**作用**：
- 验证控制端确实知道设备端的安全密码
- 完成双向验证的第二步
- 绑定成功，建立完整的控制关系

✅ **绑定完成**！

---

#### 步骤6：查询绑定状态（可选）

**操作端**：任意端

任意一方可以随时查询绑定状态，查看绑定是否完成、验证时间等信息。

**调用接口**：`GET /api/binding/status/{bindingId}`

## API接口详解

### 接口列表

| 序号 | 方法 | 端点 | 说明 | 调用端 | 需要Token |
|-----|------|------|------|--------|----------|
| 1 | GET | `/api/binding/qrcode` | 获取控制端用户名（生成二维码） | 控制端 | ✅ |
| 2 | POST | `/api/binding/create` | 创建绑定记录 | 设备端 | ❌ |
| 3 | POST | `/api/binding/verify-device` | 设备端验证安全密码 | 设备端 | ✅ |
| 4 | GET | `/api/binding/pending` | 查询待验证的绑定 | 控制端 | ✅ |
| 5 | POST | `/api/binding/verify-control` | 控制端验证安全密码 | 控制端 | ✅ |
| 6 | GET | `/api/binding/status/{id}` | 查询绑定状态 | 任意端 | ❌ |
| 7 | GET | `/api/binding/list` | 获取已绑定列表 | 设备端 | ✅ |
| 8 | DELETE | `/api/binding/unbind/{id}` | 解绑 | 设备端 | ✅ |

### 1. 获取二维码数据

**接口**：`GET /api/binding/qrcode`

**请求头**：
```http
Authorization: Bearer {control_jwt_token}
```

**请求示例**：
```bash
curl -X GET http://localhost:9999/api/binding/qrcode \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
```

**成功响应** (200 OK)：
```json
{
    "controlUsername": "xyz789",
    "message": "请在设备端扫描此二维码"
}
```

**前端处理**：
```javascript
// 生成二维码
QRCode.toDataURL(data.controlUsername, (err, url) => {
    document.getElementById('qrcode').src = url;
});
```

**错误响应** (400 Bad Request)：
```json
{
    "error": "Token无效或已过期"
}
```

### 2. 创建绑定记录

**接口**：`POST /api/binding/create`

**请求头**：
```http
Content-Type: application/json
```

**请求体**：
```json
{
    "deviceUsername": "abc123",  // 当前登录的设备端用户名
    "controlUsername": "xyz789"  // 扫码获取的控制端用户名
}
```

**请求示例**：
```bash
curl -X POST http://localhost:9999/api/binding/create \
  -H "Content-Type: application/json" \
  -d '{
    "deviceUsername": "abc123",
    "controlUsername": "xyz789"
  }'
```

**成功响应** (200 OK)：
```json
{
    "success": true,
    "bindingId": 1,
    "deviceUsername": "abc123",
    "controlUsername": "xyz789",
    "status": "PENDING",
    "deviceVerified": false,
    "controlVerified": false,
    "message": "绑定记录已创建，请双方输入安全密码"
}
```

**错误响应** (400 Bad Request)：
```json
{
    "error": "设备端用户不存在"
}
```

```json
{
    "error": "控制端用户不存在"
}
```

```json
{
    "error": "该用户不是设备端"
}
```

```json
{
    "error": "已经绑定过该控制端"
}
```

```json
{
    "error": "已达到最大绑定数量限制：5"
}
```

### 3. 设备端验证安全密码

**接口**：`POST /api/binding/verify-device`

**请求头**：
```http
Authorization: Bearer {device_jwt_token}
Content-Type: application/json
```

**请求体**：
```json
{
    "bindingId": 1,
    "secondaryPassword": "second456"  // 设备端的安全密码
}
```

```bash
curl -X POST http://localhost:9999/api/binding/verify-device \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." \

    "bindingId": 1,
    "secondaryPassword": "second456"

```

```bash
curl -X GET http://localhost:9999/api/binding/pending \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
```

**成功响应 - 有待验证的绑定** (200 OK)：
```json
{
    "bindings": [
        {
            "bindingId": 1,
            "deviceUsername": "abc123",
            "deviceId": "9F0B44DC-76A5-433B-8DB8-D3187E05A459",
            "deviceVerified": true,
            "controlVerified": false,
            "createdAt": "2025-11-25T10:30:00",
            "deviceVerifyTime": "2025-11-25T10:30:15"
        }
    ],
    "count": 1

```

**成功响应 - 没有待验证的绑定** (200 OK)：
```json
{
    "bindings": [],
    "count": 0
}
```

**说明**：
- 只返回状态为PENDING，且设备端已验证但控制端未验证的绑定
- 控制端可以定期调用此接口（建议3-5秒）
- 或者使用WebSocket接收通知

## 数据库设计

### DeviceBinding表结构

**表名**：`device_binding`

| 字段名 | 类型 | 长度 | 可空 | 默认值 | 说明 |
|--------|------|------|------|--------|------|
| id | BIGINT | - | NO | AUTO_INCREMENT | 主键 |
| device_user_id | BIGINT | - | NO | - | 设备端用户ID |
| control_user_id | BIGINT | - | NO | - | 控制端用户ID |
| device_id | VARCHAR | 255 | YES | NULL | 设备ID（从设备端用户复制） |
| control_username | VARCHAR | 100 | NO | - | 控制端用户名 |
| device_verified | BOOLEAN | - | NO | FALSE | 设备端是否已验证 |
| control_verified | BOOLEAN | - | NO | FALSE | 控制端是否已验证 |
| status | VARCHAR | 20 | NO | 'PENDING' | 绑定状态：PENDING/ACTIVE/INACTIVE |
| device_verify_time | DATETIME | - | YES | NULL | 设备端验证时间 |
| control_verify_time | DATETIME | - | YES | NULL | 控制端验证时间 |
| bind_complete_time | DATETIME | - | YES | NULL | 绑定完成时间 |
| created_at | DATETIME | - | NO | CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | - | NO | CURRENT_TIMESTAMP ON UPDATE | 更新时间 |

### 索引

```sql
-- 主键索引
PRIMARY KEY (id)

-- 查询设备端绑定
INDEX idx_device_user (device_user_id, status)

-- 查询控制端绑定
INDEX idx_control_user (control_user_id, status)

-- 查询待验证绑定
INDEX idx_pending (control_user_id, status, device_verified, control_verified)

-- 防止重复绑定
UNIQUE INDEX uk_device_control (device_user_id, control_user_id, status)
```

### 状态流转图

```
创建绑定
   ↓
PENDING (deviceVerified=false, controlVerified=false)
   ↓
设备端验证成功
   ↓
PENDING (deviceVerified=true, controlVerified=false)
   ↓
控制端验证成功
   ↓
ACTIVE (deviceVerified=true, controlVerified=true) ✅ 绑定完成
   ↓
用户手动解绑
   ↓
INACTIVE
```

    private var currentBindingId: Int?
    private let baseURL = "http://yourserver.com:9999"
    
    // MARK: - UI Components
    private let scanView: UIView = {
        let view = UIView()
        view.backgroundColor = .black
        return view
    }()
    
    private let tipLabel: UILabel = {
        let label = UILabel()
        label.text = "请扫描控制端的二维码"
        label.textColor = .white
        label.textAlignment = .center
        return label
    }()
    
    // MARK: - Lifecycle
    override func viewDidLoad() {
        super.viewDidLoad()
        title = "扫码绑定"
        setupUI()
        setupScanner()
    }
    
    override func viewWillAppear(_ animated: Bool) {
        super.viewWillAppear(animated)
        startScanning()
    }
    
    override func viewWillDisappear(_ animated: Bool) {
        super.viewWillDisappear(animated)
        stopScanning()
    }
    
    // MARK: - Setup
    private func setupUI() {
        view.backgroundColor = .black
        
        view.addSubview(scanView)
        view.addSubview(tipLabel)
        
        scanView.frame = view.bounds
        tipLabel.frame = CGRect(x: 20, y: view.bounds.height - 100, 
                               width: view.bounds.width - 40, height: 40)
    }
    
    private func setupScanner() {
        guard let device = AVCaptureDevice.default(for: .video) else {
            showAlert(message: "无法访问摄像头")
            return
        }
        
        do {
            let input = try AVCaptureDeviceInput(device: device)
            captureSession = AVCaptureSession()
            captureSession?.addInput(input)
            
            let output = AVCaptureMetadataOutput()
            captureSession?.addOutput(output)
            
            output.setMetadataObjectsDelegate(self, queue: DispatchQueue.main)
            output.metadataObjectTypes = [.qr]
            
            previewLayer = AVCaptureVideoPreviewLayer(session: captureSession!)
            previewLayer?.frame = scanView.bounds
            previewLayer?.videoGravity = .resizeAspectFill
            scanView.layer.addSublayer(previewLayer!)
            
        } catch {
            showAlert(message: "相机初始化失败: \(error.localizedDescription)")
        }
    }
    
    private func startScanning() {
        if captureSession?.isRunning == false {
            DispatchQueue.global(qos: .userInitiated).async { [weak self] in
                self?.captureSession?.startRunning()
            }
        }
    }
    
    private func stopScanning() {
        if captureSession?.isRunning == true {
            captureSession?.stopRunning()
        }
    }
    
    // MARK: - QR Code Delegate
    func metadataOutput(_ output: AVCaptureMetadataOutput, 
                       didOutput metadataObjects: [AVMetadataObject], 
                       from connection: AVCaptureConnection) {
        
        guard let metadataObject = metadataObjects.first,
              let readableObject = metadataObject as? AVMetadataMachineReadableCodeObject,
              let stringValue = readableObject.stringValue else {
            return
        }
        
        // 停止扫描
        stopScanning()
        
        // 震动反馈
        AudioServicesPlaySystemSound(SystemSoundID(kSystemSoundID_Vibrate))
        
        // 处理扫码结果
        handleQRCodeScanned(controlUsername: stringValue)
    }
    
    // MARK: - Binding Flow
    
    // 步骤1：扫码后处理
    private func handleQRCodeScanned(controlUsername: String) {
        // 获取当前登录的设备端用户名
        guard let deviceUsername = UserDefaults.standard.string(forKey: "username") else {
            showAlert(message: "未登录") {
                self.startScanning()
            }
            return
        }
        
        // 创建绑定记录
        createBinding(deviceUsername: deviceUsername, controlUsername: controlUsername)
    }
    
    // 步骤2：创建绑定记录
    private func createBinding(deviceUsername: String, controlUsername: String) {
        let url = "\(baseURL)/api/binding/create"
        let parameters: [String: Any] = [
            "deviceUsername": deviceUsername,
            "controlUsername": controlUsername
        ]
        
        AF.request(url, method: .post, parameters: parameters, encoding: JSONEncoding.default)
            .validate()
            .responseJSON { [weak self] response in
                switch response.result {
                case .success(let value):
                    guard let json = value as? [String: Any],
                          let success = json["success"] as? Bool,
                          success == true,
                          let bindingId = json["bindingId"] as? Int else {
                        self?.showAlert(message: "创建绑定失败") {
                            self?.startScanning()
                        }
                        return
                    }
                    
                    // 保存bindingId
                    self?.currentBindingId = bindingId
                    
                    // 弹出输入安全密码
                    self?.showSecondaryPasswordInput()
                    
                case .failure(let error):
                    var errorMessage = "创建绑定失败"
                    if let data = response.data,
                       let json = try? JSONSerialization.jsonObject(with: data) as? [String: Any],
                       let error = json["error"] as? String {
                        errorMessage = error
                    } else {
                        errorMessage = error.localizedDescription
                    }
                    
                    self?.showAlert(message: errorMessage) {
                        self?.startScanning()
                    }
                }
            }
    }
    
    // 步骤3：弹出输入安全密码对话框
    private func showSecondaryPasswordInput() {
        let alert = UIAlertController(
            title: "验证安全密码",
            message: "请输入设备端的安全密码以完成绑定",
            preferredStyle: .alert
        )
        
        alert.addTextField { textField in
            textField.isSecureTextEntry = true
            textField.placeholder = "安全密码"
            textField.keyboardType = .default
        }
        
        alert.addAction(UIAlertAction(title: "取消", style: .cancel) { [weak self] _ in
            self?.startScanning()
        })
        
        alert.addAction(UIAlertAction(title: "确定", style: .default) { [weak self] _ in
            if let password = alert.textFields?[0].text,
               !password.isEmpty,
               let bindingId = self?.currentBindingId {
                self?.verifyDevice(bindingId: bindingId, secondaryPassword: password)
            } else {
                self?.showAlert(message: "请输入安全密码") {
                    self?.showSecondaryPasswordInput()
                }
            }
        })
        
        present(alert, animated: true)
    }
    
    // 步骤4：设备端验证
    private func verifyDevice(bindingId: Int, secondaryPassword: String) {
        guard let token = UserDefaults.standard.string(forKey: "token") else {
            showAlert(message: "未登录") {
                self.startScanning()
            }
            return
        }
        
        let url = "\(baseURL)/api/binding/verify-device"
        let parameters: [String: Any] = [
            "bindingId": bindingId,
            "secondaryPassword": secondaryPassword
        ]
        let headers: HTTPHeaders = [
            "Authorization": "Bearer \(token)"
        ]
        
        AF.request(url, method: .post, parameters: parameters, 
                  encoding: JSONEncoding.default, headers: headers)
            .validate()
            .responseJSON { [weak self] response in
                switch response.result {
                case .success(let value):
                    guard let json = value as? [String: Any] else { return }
                    
                    let status = json["status"] as? String ?? ""
                    let message = json["message"] as? String ?? ""
                    
                    if status == "ACTIVE" {
                        // 绑定完成
                        self?.showAlert(message: "🎉 \(message)") {
                            self?.navigationController?.popViewController(animated: true)
                        }
                    } else {
                        // 等待控制端验证
                        self?.showAlert(message: message) {
                            self?.navigationController?.popViewController(animated: true)
                        }
                    }
                    
                case .failure:
                    var errorMessage = "验证失败"
                    if let data = response.data,
                       let json = try? JSONSerialization.jsonObject(with: data) as? [String: Any],
                       let error = json["error"] as? String {
                        errorMessage = error
                    }
                    
                    self?.showAlert(message: errorMessage) {
                        self?.showSecondaryPasswordInput()
                    }
                }
            }
    }
    
    // MARK: - Helper
    private func showAlert(message: String, completion: (() -> Void)? = nil) {
        let alert = UIAlertController(title: nil, message: message, preferredStyle: .alert)
        alert.addAction(UIAlertAction(title: "确定", style: .default) { _ in
            completion?()
        })
        present(alert, animated: true)
    }
}

            correctLevel: QRCode.CorrectLevel.H
        });

        // 开始轮询待验证的绑定

    } catch (error) {

    }

// 步骤2：轮询查询待验证的绑定
async function startPollingPendingBindings() {
    // 每3秒查询一次
    pollingInterval = setInterval(async () => {
        try {
            const response = await fetch(`${BASE_URL}/api/binding/pending`, {
                headers: {
                    'Authorization': `Bearer ${controlToken}`
                }
            });
            
            if (!response.ok) {
                console.error('查询失败');
                return;
            }
            
            const data = await response.json();
            
            if (data.count > 0) {
                // 有待验证的绑定，停止轮询
                clearInterval(pollingInterval);
                
                // 获取第一个待验证的绑定
                const binding = data.bindings[0];
                currentBindingId = binding.bindingId;
                
                // 显示设备信息
                showDeviceInfo(binding);
            }
            
        } catch (error) {
            console.error('轮询错误:', error);
        }
    }, 3000);
}

        return;

        const response = await fetch(`${BASE_URL}/api/binding/verify-control`, {

## 常见问题FAQ

### Q1: 为什么设备端和控制端都要验证安全密码？

**A**: 这是为了增强安全性。双向验证确保：
- 设备端确认：设备端用户必须输入自己的安全密码，确保是本人同意绑定
- 控制端确认：控制端用户必须知道设备端的安全密码，证明有权限控制该设备

### Q2: 控制端输入的是谁的安全密码？

**A**: 控制端输入的是**设备端的安全密码**，不是控制端自己的密码。

原因：控制端需要证明自己有权限控制设备端，所以必须知道设备端的密码。

### Q3: 为什么控制端必须在设备端验证后才能验证？

**A**: 这是为了确保绑定顺序：
1. 设备端先同意绑定（输入密码）
2. 控制端再确认绑定（输入密码）

如果允许控制端先验证，可能导致设备端还没同意，绑定就完成了，这不符合逻辑。

### Q4: 如何取消正在进行的绑定？

**A**: 
- 设备端：直接关闭页面或返回，绑定记录会保持PENDING状态
- 控制端：停止轮询并刷新页面即可

PENDING状态的绑定记录可以设置定期清理任务（如24小时后自动删除）。

### Q5: 绑定后设备ID是如何同步的？

**A**: 当双方验证成功后：
1. 控制端用户的 `deviceId` 字段被设置为设备端的 `deviceId`
2. 这样控制端就可以使用这个 `deviceId` 来控制设备了

### Q6: 一个设备端最多可以绑定多少个控制端？

**A**: 默认是5个，可以通过系统配置 `max_bind_count` 修改。

```sql
INSERT INTO system_config (config_key, config_value, description)
VALUES ('max_bind_count', '10', '每个设备端最多绑定的控制端数量');
```

### Q7: 控制端可以绑定多个设备端吗？

**A**: 可以。一个控制端可以绑定多个设备端，没有数量限制（但取决于业务需求）。

### Q8: 绑定后如何解绑？

**A**: 设备端可以调用解绑接口：

```bash
DELETE /api/binding/unbind/{bindingId}
```

解绑后，绑定记录状态变为 `INACTIVE`，控制端失去控制权限。

### Q9: 如何防止恶意绑定？

**A**: 系统有多重保护：
1. 需要设备端用户同意（输入安全密码）
2. 需要控制端用户知道设备端密码
3. JWT token认证，防止未授权访问
4. 绑定数量限制，防止滥用
5. 可以随时解绑

### Q10: 绑定流程中断了怎么办？

**A**: 
- 如果设备端验证后，控制端没有验证，绑定记录会保持PENDING状态
- 控制端可以随时查询待验证的绑定并完成验证
- 或者重新扫码创建新的绑定记录

### Q11: 为什么不使用WebSocket而用轮询？

**A**: 两种方式都支持：
- **轮询**：简单易实现，兼容性好，推荐用于快速开发
- **WebSocket**：实时性更好，服务器压力更小，推荐用于生产环境

可以根据实际需求选择。

## 安全注意事项

### 1. Token安全

✅ **建议**：
- 使用HTTPS传输，防止Token被窃取
- Token设置合理的过期时间（如24小时）
- Token存储在安全位置（iOS Keychain / Android EncryptedSharedPreferences）

❌ **避免**：
- 不要在URL中传递Token
- 不要将Token写入日志
- 不要在前端JavaScript中明文存储Token

### 2. 安全密码安全

✅ **建议**：
- 安全密码使用bcrypt等安全算法加密存储
- 验证失败次数限制（如5次错误后锁定1小时）
- 密码复杂度要求（如至少6位）

❌ **避免**：
- 不要明文存储安全密码
- 不要在日志中记录安全密码
- 不要在响应中返回安全密码

### 3. 绑定限制

✅ **建议**：
- 设置合理的绑定数量限制
- 记录绑定操作日志，便于审计
- 异常绑定行为监控（如短时间内大量绑定）

### 4. API安全

✅ **建议**：
- 所有API使用HTTPS
- 添加请求频率限制（Rate Limiting）
- 输入验证和SQL注入防护
- CORS配置限制来源

### 5. 数据隐私

✅ **建议**：
- 敏感数据加密存储
- 遵守GDPR等隐私法规
- 用户数据定期清理
- 提供数据导出和删除功能

### A. 完整的状态码说明

| HTTP状态码 | 说明 | 常见原因 |
|-----------|------|---------|
| 200 OK | 请求成功 | - |
| 400 Bad Request | 请求参数错误 | 缺少必需参数、参数格式错误 |
| 401 Unauthorized | 未授权 | Token无效、Token过期 |
| 403 Forbidden | 禁止访问 | 权限不足 |
| 404 Not Found | 资源不存在 | 绑定记录不存在、用户不存在 |
| 500 Internal Server Error | 服务器错误 | 后端异常 |

### B. 数据库查询语句示例

```sql
-- 查询设备端的所有绑定
SELECT * FROM device_binding
WHERE device_user_id = ? AND status = 'ACTIVE'
ORDER BY bind_complete_time DESC;

-- 查询控制端待验证的绑定
SELECT * FROM device_binding
WHERE control_user_id = ? 
  AND status = 'PENDING'
  AND device_verified = TRUE
  AND control_verified = FALSE;

-- 统计设备端已绑定数量
SELECT COUNT(*) FROM device_binding
WHERE device_user_id = ? AND status = 'ACTIVE';

-- 清理超过24小时的PENDING绑定
DELETE FROM device_binding
WHERE status = 'PENDING'
  AND created_at < DATE_SUB(NOW(), INTERVAL 24 HOUR);
```
